# MTMB 디자인 스튜디오

제안서를 만들수록 똑똑해지는 공장.

**옆 패널(눌러볼 수 있는 화면):** https://claude.ai/artifact/V3Awej6QJkZcUmUQGfyCtS

---

## 1. 이게 무엇인가

제안서를 만들면 끝나는 도구가 아니다. **쓸수록 결과가 좋아지는 구조**다.

```
제안서를 만든다 → 대표가 고친다 → 고친 내용이 창고에 남는다
                                      ↓
                   규칙이 쌓이고 · 사례가 모이고 · 페이지 타입이 늘고
                                      ↓
        다음부터 AI 가 그걸 전부 읽고 만든다 → 결과가 점점 좋아진다
```

## 2. 창고 5개 — 여기에 쌓인다

| 창고 | 무엇이 쌓이나 | 어디서 보나 |
|---|---|---|
| **스타일** | 색, 글꼴, 글자 크기, 여백 | `스타일` 화면 |
| **페이지 타입** | 표지·요약·숫자 임팩트… 계속 추가됨 | `스타일` 화면 아래 |
| **규칙** | "앞으로도 이렇게" 목록. 켜기/끄기 | `규칙` 화면 |
| **사례** | 만든 제안서들. AI 가 참고한다 | `보관함` |
| **수정 기록** | 지시문 + 전/후 | 저장만 됨 (화면은 2차) |

AI 를 부를 때마다 이 창고를 **전부 읽어서** 같이 넘긴다. 창고가 커지면 결과가 좋아진다.

## 3. 쓰는 순서

1. **새 제안서** → 이름·고객사 적고, 내용을 붙여넣는다
2. **AI 초안 만들기** → 페이지 구성이 짜여서 나온다
3. **한 장씩 고친다** — 오른쪽에 지시를 적으면 그 페이지만 다시 그려진다
4. 지시가 "앞으로도 이렇게"면 **원칙으로 저장** 버튼이 뜬다 → 규칙 창고에 쌓인다
5. **PPT 내보내기**

빨간 `[ 확인 필요 ]` 는 아직 안 채운 칸이다. 위쪽에 몇 개 남았는지 나온다.

## 4. 내 PC 에서 돌리기

```bash
npm install
npm run dev          # 브라우저에서 http://localhost:5173 열기
```

AI 기능을 쓰려면 이 폴더에 **`.env.local`** 파일을 만들고 한 줄 적는다.

```
ANTHROPIC_API_KEY=여기에_열쇠를_붙여넣기
```

열쇠는 https://console.anthropic.com 에서 발급한다.

**카피 작업실(ChatGPT)** 도 쓰려면 같은 파일에 두 줄을 더 적는다.

```
OPENAI_API_KEY=여기에_ChatGPT_열쇠
OPENAI_MODEL=gpt-5
```

`OPENAI_MODEL` 은 쓰는 모델 이름이다. 이름이 틀리면 화면에 그대로 알려주니
그때 고쳐 적으면 된다.

이 열쇠들은 **내 컴퓨터 안에만** 있고 브라우저로 나가지 않는다.
적은 뒤에는 `npm run dev` 를 다시 켜야 한다.

### 두 AI 의 역할

| | 맡는 일 | 어디서 되나 |
|---|---|---|
| **Claude** | 화면을 **보고** 레이아웃·구성·규격 | 옆 패널 · 내 PC 둘 다 |
| **ChatGPT** | **글만**. 카피·톤·길이 | 내 PC 에서만 |

둘 다 **같은 규칙 창고를 읽는다.** 안 그러면 ChatGPT 가 쌓아둔 원칙 밖의
문구를 뱉고, 그걸 다시 고치느라 일이 늘어난다.

카피 작업실은 편집기 위쪽 `카피 작업실` 버튼으로 연다.
`이 페이지 문구 가져오기` → 다듬기 → `바꾸기` 로 페이지에 바로 반영된다.

## 5. 구조 — 어디를 고치면 무엇이 바뀌나

| 바꾸고 싶은 것 | 고칠 파일 |
|---|---|
| 색·글자 크기 (전체가 한 번에 바뀜) | `src/core/style.ts` |
| 페이지 모양·새 페이지 타입 | `src/core/pageTypes.ts` |
| 기본 규칙 목록 | `src/store/db.ts` |
| AI 에게 주는 지시문 | `src/ai/brain.ts` |
| 저장 장소 (나중에 Firebase 로) | `src/store/db.ts` **이 파일만** |

### 미리보기와 PPT 가 왜 똑같은가

레이아웃 정의가 **하나뿐**이다.

```
페이지 모양(데이터) + 내용 + 스타일
          │
     해석기 (src/core/interpret.ts)
          │
     그리기 명령 목록
        ╱       ╲
  화면 미리보기   PPT 파일
```

둘 다 **같은 그리기 명령만** 보고 그린다. 좌표를 두 번 계산하지 않는다.
그래서 "화면과 PPT 가 다르다"는 일이 구조적으로 생길 수 없다.

좌표는 대표님이 승인한 `인천시티투어_제안서_v10.pptx` 에서 그대로 뽑았다.
